## Phase 3a — `:shared` foundation (2026-11-01)

**Toolchain: unchanged (Kotlin 2.4.21, Compose Multiplatform 1.12.2, Skiko 0.150.2).** No stable combination removes both Wasm problems, and nothing was patched. Findings from release notes, Maven Central and source:
- Resources `isWasmExportsAvailable` console error: fixed upstream only in **Compose Multiplatform 1.13.0-beta01** (2026-10-23, [release](https://github.com/JetBrains/compose-multiplatform/releases/tag/v1.13.0-beta01)): its [`WasmByteArrayUtils.kt`](https://raw.githubusercontent.com/JetBrains/compose-multiplatform/v1.13.0-beta01/components/resources/library/src/wasmJsMain/kotlin/org/jetbrains/compose/resources/WasmByteArrayUtils.kt) uses `kotlin.wasm.unsafe.wasmMemory`, and it pulls Skiko 0.156.0 (which migrated Skiko itself, [Skiko 0.155.0](https://github.com/JetBrains/skiko/releases/tag/v0.155.0)). 1.12.1 and 1.12.2 do not contain it. 1.13.0 is not stable yet (and Material 3 would move 1.9.0 to 1.5.0 and could change Android rendering), so it was not adopted.
- Skiko WebKit invalid-enum error: **not fixed** in any Skiko release through 0.156.1. The Emscripten glue in `skiko-wasm-js-0.156.0-skiko-runtime.jar` still calls `getParameter(37446)` (unmasked renderer) without enabling `WEBGL_debug_renderer_info`, same as 0.150.2.
- Recommendation: stay on 1.12.2 for now. For the Phase 3b smoke test either (a) allow-list exactly that WebKit `INVALID_ENUM` console message (it is a browser-side warning, no functional effect observed in the probe) and move to Compose Multiplatform 1.13.0 stable when released (then no resource patch is needed), or (b) if the owner wants zero console errors on 1.12.2, apply the two build-time loaders from the probe. A Kotlin downgrade to 2.4.10 was not tried; it would not address the Skiko enum.

## Phase 4a — workouts run on the web (2026-11-02)

**Shared runner.** `WorkoutSessionService`'s platform-independent body is now `SessionRunner` (`:shared` commonMain): reducer events applied one at a time (a `Mutex` over a serial dispatcher, replacing the single-thread executor), 200 ms ticker, checkpoint every 5 s and on `Persist`, cues, finished-session save through `PlatformContext.historyRepository()`, `CheckpointStore` clear after the save, `SessionBus` as the single state source. Nothing is copied: Android and web both construct it. Platform parts sit behind two small interfaces, `SessionHost` (keep-awake, call-state, notification refresh, release) and `CuePlayer` (load/await/refresh/cue/say/release). `AppAudioGain.kt` moved to `:shared` (functions now public; `AppAudioGainTest` unchanged).

**Android (behaviour unchanged).** `WorkoutSessionService` (349 → ~150 lines) is a thin host: Intents (same actions/extras), foreground notification + actions, `PARTIAL_WAKE_LOCK` (same durations), `AudioManager` call-state check, a single-thread executor as the runner's dispatcher, and `AndroidCuePlayer` (the SoundPool/`CuePlaybackPipeline`/TextToSpeech code moved verbatim; the pipeline, `CueAudioSink` and their tests stay in `:app`). Checkpoint codec/format and recovery are untouched. `CuePlayback.kt` and `SessionWindowPolicy.kt` stay.

**Web.** `WebSession` (wasmJs) owns one `SessionRunner` on `Dispatchers.Default`; `startWorkout`/`recoverWorkout`/`sessionCommand`/`logBlock` call it directly. Timers: the reducer's deadlines run on `elapsedRealtimeMs()` = `SleepAwareClock(performance.now, Date.now)` (new in `:domain`, 3 tests): a gap between wall and monotonic time (phone asleep) is added, so remaining time is right on return. `visibilitychange` → `tick()` immediately; hide/`pagehide` → synchronous checkpoint. Checkpoint lives in the web settings store (`workout_checkpoint`/`json`, existing `CheckpointStore`), so a reload offers "Continue it (paused)" / "Save what was done and end" like Android. Cues: Web Audio beeps are **synthesized** (sine tones: start 1320 Hz, warning 1000 Hz, finished 660/880/1100 Hz; the `.ogg` samples are not used because Safari's Ogg Vorbis support is unreliable) at the saved app volume; voice via `speechSynthesis` (en-US, rate 0.75, volume = app gain, flush like `QUEUE_FLUSH`), honouring the audio-enabled preference. Audio/speech are unlocked by capture-phase listeners on the first pointer/touch/key event (installed at startup). Keep-alive: Screen Wake Lock requested at start, re-requested when the page becomes visible, released at the end; errors/unsupported are ignored. `globalThis.__calAudio` counts beeps and spoken texts (read by the smoke test).

**Known web limits.** Cues (beeps, voice) and timers pause being delivered while the page is hidden or the phone is locked (browsers throttle/suspend page timers and block audio without a visible page); the display time is recomputed on return, but missed cues are not replayed. The Screen Wake Lock is dropped by the browser when hidden and re-acquired on return; unsupported browsers just let the screen sleep. Sleep detection treats a wall clock set forwards by more than 1 s as sleep. Android notification actions and call-state interruption have no web equivalent. Back navigation is still a no-op on web.
