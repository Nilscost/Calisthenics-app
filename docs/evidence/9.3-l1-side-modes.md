# 9.3 L1: side modes (per-side clarity)

Rule (owner, doc 43 row 1): the stored number is per side; an ALTERNATING exercise shows "16 reps (8 per side)" in Preview, the workout, the logger and History.
Numbers are unchanged, except the plank shoulder tap (9.2 stored totals, now per side). Source: `ALTERNATING_ADDED_IDS` in `tools/gen_r8_catalog.py`;
the guard is `SideModeTest.nothingThatSaysItAlternatesSidesIsLeftWithoutASideMode`, whose allow-list is `noneOnPurpose`.

How I decided: ALTERNATING when one continuous set switches sides and a count is one side's movement (a step, a twist, a limb reach), so the number reads naturally per side.
NONE when the number is a total of whole movements (heavy pulls, plyometrics, distance and cadence drills, timed items) or when the source says so (routine-only Army drills).

Totals the screen shows after the change are twice the stored number, so a lunge ladder of 6/8/10/12/16 reads 12/16/20/24/32 in all. Only the display changes; an alternating
block is planned twice as long as its per-side window, which is how the other ten alternating exercises already behave.

## Fixed programs

`_apply_side_modes` requires a program item to be `perSide` exactly when its exercise is SPLIT or ALTERNATING. Three programs held newly alternating exercises as totals:
`army-prt` and `army-pd`: walking-lunge 10 and windshield-wiper-bent-knee 10 became 5 per side (shown "10 reps (5 per side)"), estSeconds 48 to 24. Source totals are kept.
The generator halves a total only for `ALTERNATING_ADDED_IDS` and fails on an odd number.

## Shoulder tap: how history stays put

Replay reads each session's own prescribed level and policy snapshot (stored in the plan), never today's catalog numbers, so a 9.2 session (snapshot 10/12/14/16/20 in total)
replays to the same level, stars and streak under the 9.3 catalog (`PerSideReplayTest`). An old total (16 taps) is judged against its own snapshot (level 4), never against the
per-side ladder where it would look like level 5. The first session after the update carries the new snapshot; 7 per side equals the old 14 in total, so the good-session count
continues ("2 of 3" stays "2 of 3"). No `targetRevision` is stamped: that would clear streaks, and it is compared with the owner's own personal-target edits, so I did not use it.
