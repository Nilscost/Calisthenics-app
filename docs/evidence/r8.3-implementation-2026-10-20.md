## Contracts, compatibility and migrations

All serialized additions are appended with defaults. `BetweenSetMode?` is authoritative when present; old data maps Flow=true to Flow, otherwise Stretch=true to Stretch, otherwise Rest. Legacy booleans remain readable. Preparation defaults to 5 and is clamped to 1–30 at planning/persistence boundaries.

Personal definitions contain a revision, five values and an edit timestamp in app-private preferences. `Catalog.personalTargets` resolves them per exercise without mutating a shared authored policy. New blocks snapshot the definition revision. Replay preserves old earned results, clears incompatible pending streaks, and refuses post-edit results from stale saved plan definitions. New definition fields survive backup/restore, along with volume and the new workout settings. Reset creates a revision so an older streak is not reused.

`PlanEdits.levelFiveTargets` and program-item app-level/extension metadata identify new deliberate extensions. `TimelineBlock.levelFiveEligible` defaults false, so historical arbitrary free targets are not reclassified. Evidence rejects wrong-unit, skipped, partial, incomplete and mixed prescriptions. Flow program results require actual per-block log/correction provenance; timer-only authored results remain without strength evidence. History retains actual reps/seconds. Above-threshold evidence establishes a fresh level-5 streak when appropriate; only the normal accomplishment gate adds its lower attained tiers and fifth star.

No Room entity or schema changed, so no Room migration was needed. The existing migration SQL check passes. The debug seed was regenerated for compatible serialized plan/preference additions. Historical plans are read as stored, not rewritten.

## Android audio behavior reviewed

Android's [audio focus guide](https://developer.android.com/media/optimize/audio-focus) describes focus requests and the associated pause/duck behavior. Removing those requests avoids this app asking another player to yield or duck; this is an implementation choice, not proof of every vendor/player interaction. [SoundPool](https://developer.android.com/reference/android/media/SoundPool) exposes per-stream 0–1 left/right gain; [TextToSpeech volume](https://developer.android.com/reference/android/speech/tts/TextToSpeech.Engine#KEY_PARAM_VOLUME) and [audio attributes](https://developer.android.com/reference/android/speech/tts/TextToSpeech#setAudioAttributes(android.media.AudioAttributes)) expose app-only speech controls. The saved percentage is converted to a bounded linear gain for these APIs; it never changes system media volume. Speech initialization/failure is independent of workout ticks. Phone checks must cover downloaded local music over speakers and Bluetooth.
