## 2. Android `res/values/strings.xml` mirror

Left in place (no change). Numbers:

- `app/src/main/res/values/strings.xml`: 603 lines (582 `<string>` entries), plus 3 feedback_*.xml files (24 lines) with the same pipeline. `shared/.../composeResources/values/strings.xml` is generated from them by `tools/convert_strings.py` (608 entries); `scripts/verify.sh` runs `convert_strings.py --check`.
- Runtime use of the Android copy: one string, `@string/app_name` (twice, as labels in `AndroidManifest.xml`). No `R.string` in any main source set of `app`, `data`, `shared` or `domain`; no `@string/` in other resource XML.
- Test use: 7 `R.string` references in 2 test files (`SessionScreenTest.kt` 4, `EndScreenTest.kt` 3): `demo_clip_description`, `session_starting`, `end_saving`, `end_save_failed`, `end_saved`. (`EndScreenTest`, `TrainScreenTest`, `PreviewScreenTest` also match `getString(` but those are not `R.string`.)
- So Android itself needs about 6 strings, but they are the generator's source of truth: removing the mirror means making the shared Compose `strings.xml` the source, changing the direction of `convert_strings.py` and the `verify.sh` step, and pointing the tests at Compose resources. That is the larger change doc 43 excludes, so it was not done.
- Recommendation: a follow-up change that makes `shared/.../composeResources/values/strings.xml` the source, deletes `convert_strings.py` and the `--check` step, keeps a 1-line `app_name` in `app/src/main/res/values/strings.xml`, and switches the 5 test strings to `Res.string.*` (or literals).
